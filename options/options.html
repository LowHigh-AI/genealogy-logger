First-Time Setup Guide

~5 minutes

You only do this once. It connects three things: a Google Sheet to store records, an Apps Script that writes to it, and a Gemini key that reads the documents.

  1. Get a free Gemini API key. Go to Google AI Studio, sign in, click Create API key, and copy it (it starts with AIzaSy…).
  2. Open your Sheet's script editor. Create a sheet at sheets.new (or open an existing one), then choose Extensions > Apps Script from its menu. Starting from inside the sheet matters — it links the script to that sheet.
  3. Paste in the script. Delete the sample code, paste in Code.gs, and save with ⌘+S / Ctrl+S.
  4. Add the permissions manifest. Click the gear icon (Project Settings) and tick "Show 'appsscript.json' manifest file in editor". Go back to the editor, open the new appsscript.json, and replace it with the one from the same folder. Skipping this causes the most common failure: "You do not have permission to call UrlFetchApp.fetch."
  5. Add your two secrets. In Project Settings > Script Properties, add:
    • GEMINI_API_KEY — the key from step 1.
    • GAS_SECRET_KEY — any password you invent. You'll paste the same one into Step 2 above.
    • GEMINI_MODEL — optional. Only needed to override the default model, e.g. after Google retires one.
  6. Authorize the script. Pick forceAuth in the function dropdown at the top and click Run. Approve the prompt: Advanced → Go to … (unsafe) → Allow. The warning is Google flagging your own unverified script — it's expected. Note which account the log line names; the script runs as that account from now on.
  7. Deploy it as a web app. Deploy > New deployment > Web app, with Execute as: Me and Who has access: Anyone. Click Deploy and copy the Web app URL.
  8. Fill in the fields above — the web app URL, your GAS_SECRET_KEY, your sheet's URL, and optionally a Drive folder for scans — then click Save Settings followed by Test Connection. Success names both the sheet and the folder it will write to.
  9. Optional: add your family lines. Each one gets its own tab in the sheet. Pick the active one from the extension popup before logging; it stays selected until you change it.

Troubleshooting & FAQ

"You do not have permission to call UrlFetchApp.fetch"

The script was never granted the script.external_request scope, which it needs to reach Gemini. Do steps 4 and 6 of the guide: add appsscript.json, then run forceAuth and approve the prompt.

Running doGet will not trigger the prompt — it touches no protected services, so Google has nothing to ask about. And the log button can't trigger it either: those requests arrive anonymously, with no browser session to show a dialog in.

"Service Spreadsheets failed while accessing document with id …"

That ID doesn't point to a sheet the script's account can open — it's wrong, deleted, or owned by a different Google account.

Paste your sheet's full URL into Step 3 above and save. If it still fails, compare the account forceAuth logged against the account that owns the sheet: a web app runs as whoever deployed it, not as whoever is using the extension.

"models/… is not found for API version v1beta" (404)

Google retired the model the script was set to use. You don't need to edit the code — the error message now lists the model ids your key can actually call.

Pick one and add it as a GEMINI_MODEL script property in your Apps Script project (Project Settings > Script Properties). To see the full list yourself, run listGeminiModels from the editor's function dropdown and check the execution log.

How do I change which Gemini model is used?

Use Step 5 above. Click Refresh list and the dropdown fills with the models your API key can actually call right now — the list comes from Google, so a retired model simply stops appearing.

Leave it on Automatic to let the script decide (its GEMINI_MODEL script property, or its built-in default). Refreshing needs your webhook URL and API key saved first, since the Gemini key lives in the Apps Script project rather than in the extension.

"403 Forbidden" when logging

The API key in Step 2 doesn't match the GAS_SECRET_KEY script property in your Apps Script project. They must be identical, including case. If you never set that property, the script falls back to GENEALOGY_SECRET_2026.

Does my web app URL change when I redeploy?

Only if you create a new deployment. To publish code changes without changing the URL, use Deploy > Manage deployments, click the pencil on the existing deployment, set Version: New version, and deploy.

Choosing "New deployment" each time leaves old deployments running old code at old URLs, which gets confusing fast. Editing the script and saving alone changes nothing that's live — you must push a new version.

I edited the script but nothing changed

Saving in the editor doesn't update the live web app. Deploy a new version (see above). If you changed extension files instead, reload the extension at chrome://extensions.

My columns don't line up with the headers

This self-corrects now. On every log, the script checks row 1 against the expected columns and rewrites it if it doesn't match, so a tab created under an older layout gets repaired automatically.

Rows written before that fix aren't moved — their values still sit under whatever columns they landed in, so older entries may need a manual once-over.

What are Family Lines, and what do they do?

They're your research targets — typically one per ancestral surname. Add them in the card above, then pick the active one from the extension popup. Each line writes to its own tab in your sheet, created automatically on first use.

Your choice persists until you change it, so a research session on one branch stays in one place. Removing a line only takes it out of the picker; the tab and its records stay.

Where do the document images go?

Into whichever folder you set in Step 4 above, or a Genealogy Document Clippings folder created automatically if you leave that blank. Either way they're filed in a subfolder named for the surname Gemini detected, and the sheet's "Document Scan" column links to each file.

That surname grouping is automatic and separate from the family-line tab you selected.

Can I choose where document scans are saved?

Yes — click Browse… next to Step 4 and pick the folder, or paste its address if you prefer. The same works for your sheet in Step 3.

Browsing goes through your own Apps Script rather than asking you to sign in again, so there's no extra Google permission to grant — and everything listed is guaranteed to be visible to the account that does the writing.

Inside whichever folder you pick, scans are still sorted into a subfolder named for the surname Gemini detected in the record. Leave the field blank and the script falls back to a Genealogy Document Clippings folder it creates in the Drive of the account running the script. Test Connection reports the folder it resolved, so you can confirm it before logging anything.

Who can see my data?

There's no server in the middle. The page text and image go from your browser to your own Apps Script, which calls Gemini with your own API key and writes to your own sheet and Drive.

Your web app is deployed as "Anyone", so treat the URL and API key as a password pair — together they let someone write to the sheets and Drive of the account that deployed it.

Nothing is detected on the page I'm viewing

The extension reads the page you have open, so make sure the record itself is on screen and expanded before clicking the icon. It can't read chrome:// pages or the Chrome Web Store. If no image is found it falls back to a screenshot of the visible area — so scroll the document into view first.
